## 概述
在云原生和混合云环境中，有效监控和理解云服务（如 AWS RDS、Azure VM、GCP Cloud SQL）的状态对于维持系统可靠性至关重要。Grafana Cloud 提供的云服务可观测性功能，其核心价值之一在于提供了开箱即用的预配置仪表板和下钻视图。然而，每个组织都有其特定的监控重点、工作流和已建立的仪表板。本文阐述了如何在 Grafana Cloud 中自定义这些预配置视图，以满足特定团队的监控需求，确保在故障排查和性能优化时能够获得最相关、最熟悉的数据视角。

## 核心概念
Grafana Cloud 中云服务可观测性的定制化能力主要围绕三个核心概念展开，它们共同允许用户在保留预置视图灵活性的同时，无缝集成个性化工作流：

1.  **快速链接与默认仪表板**：此功能允许您为特定云服务（例如 Amazon RDS）关联一个已有的或新建的 Grafana 仪表板作为快捷入口。通过将其设为“默认”，当用户从服务列表、实体图谱（Entity Graph）或数据库可观测性（Database Observability）等入口点访问该服务时，系统将直接展示此自定义仪表板，而非预置的通用视图。这确保了团队始终从最熟悉的界面开始分析。
2.  **实例钻取视图**：当用户从服务概览深入到单个实例（如一个特定的 RDS 实例或 Lambda 函数）时，系统会展示实例钻取视图。该视图由一组预定义的指标面板和查询构成。您可以通过自定义此视图，控制在该层级显示哪些具体指标、查询如何组织、以及面板的布局和单位。此配置在整个 Grafana Cloud 生态（包括云服务可观测性、数据库可观测性和实体图谱）中统一生效，保证了分析路径的一致性。
3.  **AI生成仪表板**：对于希望快速获得符合行业最佳实践（如 RED/USE 方法论）的仪表板但又不想从零构建的场景，可以利用 AI 生成仪表板。该功能会创建一个包含正确变量和面板的起点仪表板，用户可以对其进行调整，然后像普通自定义仪表板一样添加到服务链接中，甚至设为默认视图。

## 实践
所有云服务的自定义操作都集中在该服务的“配置”（Configure）页面。在 Grafana Cloud 的“服务”选项卡中，点击目标服务旁的 **Configure** 即可进入。

### 1. 连接现有仪表板
如果您已经拥有一个针对特定云服务（如内部运维团队构建的 RDS 监控面板）的成熟仪表板，可以将其作为该服务的快速链接。
1.  在该服务的配置页面，找到“自定义您的快速链接并添加新的自定义仪表板”部分。
2.  在“选择仪表板”下拉菜单中，从您的 Grafana 堆栈中选择目标仪表板，然后点击 **Add**。
3.  新添加的仪表板会出现在列表中。点击其对应的 **Set as default** 即可将其设为主视图。点击 **Save** 保存配置。
4.  此后，该自定义仪表板会作为快速链接出现在服务页面顶部。若其为默认视图，则会成为应用内所有入口点进入该服务时的主要界面。

### 2. 使用AI创建并关联仪表板
如果没有现成的仪表板，可以通过 AI 快速生成一个基础版本。
1.  在同一服务的配置页面，“自定义您的快速链接...”部分，点击 **Generate with AI**。
2.  AI 将生成一个包含该服务相关指标、正确变量和标准化面板（遵循 RED/USE 方法论）的仪表板。您可以预览并保存它。
3.  保存后，可通过 Grafana Assistant 提供的链接返回配置页面。
4.  在“选择仪表板”中选中刚生成的仪表板，点击 **Add**，并根据需要设为默认，最后点击 **Save**。这个 AI 生成的仪表板现在已集成到服务工作流中，并可随时编辑。

### 3. 编辑实例钻取视图
此操作将统一修改点击任何单个云资源实例时显示的视图。
1.  在服务的配置页面，滚动到“自定义将在钻取实例视图中显示的面板”部分。
2.  开启自定义面板的开关。
3.  在可用的指标/查询选择列表中，您可以搜索、全选/反选，也可以添加自定义查询。为每个查询指定要关联的面板。
4.  在面板网格区域，您可以拖拽面板调整顺序、编辑标题、修改单位、调整每个查询的图例格式和聚合方式。也可以将查询在面板间移动或创建新面板。
5.  完成所有调整后，点击 **Save**。
配置生效后，无论是从云服务可观测性、数据库可观测性、实体图谱还是告警详情页跳转到该实例，都将显示您定制的钻取视图。

## SRE 要点
- **与可靠性及事件响应的关联**：定制化的视图直接服务于 SRE 的核心实践——快速定位问题（MTTD）和恢复服务（MTTR）。当警报触发时，响应人员能够立即进入他们信任的、包含关键诊断指标的默认仪表板，而不是在通用视图中花费时间寻找正确的数据。统一的实例钻取视图则确保了在从宏观服务监控下钻到微观实例诊断时，关键上下文和指标不丢失，极大地提升了故障排查效率。
- **最佳实践与反模式**：
    - **最佳实践**：为团队最常监控的核心服务设置默认自定义仪表板；确保实例钻取视图包含最相关的错误、延迟和资源利用率（RED/USE）指标；利用 AI 生成作为初稿，再根据业务逻辑定制。
    - **常见反模式**：为所有服务设置同一默认仪表板，忽视服务特性差异；过度定制实例视图，导致信息过载；在团队间未就“默认视图”和“钻取视图”的内容达成一致。
- **相关指标（SLI/SLO）**：定制仪表板的核心目的是更精确地展示 **SLI**。例如，对于 Web 服务，定制视图可能更突出 P99 延迟和错误率 SLI；对于数据库，可能更关注查询延迟和连接数 SLI。通过将关键 SLI 放在视图最显眼的位置，可以更直观地衡量和管理对应的 **SLO**，并与 **Error Budget** 消耗情况相关联。

通过充分利用 Grafana Cloud 的云服务可观测性定制功能，SRE 团队可以构建一个既标准化又个性化、既全局统一又细节丰富的可观测性体系，从而更自信地保障云上服务的可靠性。相关内容可参考 [[cloud-provider-observability]] 和 [[entity-graph]]。
