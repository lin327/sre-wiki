# k6 2.0 Release: AI-Assisted Testing and Extension Updates

## Overview

k6 is a widely popular open-source load testing tool designed to help teams proactively conduct performance testing, enabling early discovery and resolution of performance issues to deliver more reliable user experiences. As software delivery cycles continue to accelerate, particularly with the rise of AI-assisted development workflows, testing tools face higher demands for automation, explainability, and scalability. The k6 2.0 release addresses these challenges. Building on the stability and TypeScript support of version 1.0, it significantly enhances the creation, verification, automation, and scaling of test scripts through a series of new features, making k6 an indispensable performance verification tool in the AI-driven modern software development lifecycle.

## Core Concepts

**k6 Core Architecture**: k6 is built in Go, with test scripts written in JavaScript. Its core advantages are high performance, lightweight footprint, and clear test metrics (such as response time, throughput, error rate). It defines and executes tests through **scripts**, **checks**, **thresholds**, and **scenarios**.

**Extensions System**: This is k6's core extensibility mechanism, allowing developers to add new protocol support, clients, output formats, or CLI capabilities to k6. Extensions are divided into **official extensions** maintained by Grafana Labs and **community extensions** contributed and maintained by the community. k6 2.0 introduces a unified extension registry that clearly distinguishes between the two and provides a more standardized submission process.

**AI Integration and Programmability**: k6 2.0 transforms k6 from a simple test executor into a programmable testing platform through a series of `k6 x` subcommands. It supports the **Model Context Protocol (MCP)**, allowing AI coding assistants (such as Claude Code, Cursor, etc.) to directly invoke k6 functionality to generate, verify, and run tests, achieving deep integration between testing and AI development workflows.

**Assertions API**: Unlike existing **checks**, the Assertions API provides more granular test condition evaluation. **Non-retry assertions** check immediate state (such as HTTP status codes), while **auto-retry assertions** wait for conditions to be met or timeout (particularly useful for element appearance in browser tests). When an assertion fails, it typically means the test scenario is invalid and should be terminated, which differs from the design philosophy of checks (which record metrics but continue execution).

## Practice

**1. Setting Up AI-Assisted Testing Workflows**

Use the new commands to quickly bootstrap integration with AI agents:

- `k6 x agent`: Initializes an agent environment within supported AI coding assistants that can write correct, modern k6 tests.
- `k6 x mcp`: Starts a built-in MCP server that allows AI agents to interact with k6 through a standard protocol, retrieving resources, running scripts, and viewing results.
- `k6 x docs`: Query k6 documentation, API references, and examples directly from the command line.
- `k6 x explore`: Browse and filter the official and community extension registry, automatically discovering and integrating needed extensions.

**2. Leveraging the Extension Registry and Developer Tools**

- **Browse extensions**: Use the `k6 x explore` command or the [online registry](https://grafana.com/docs/k6/latest/extensions/explore/) to find extensions supporting specific protocols (such as MQTT, SQL, Kafka, DNS). For extensions supporting automatic resolution, simply reference them in the script and k6 handles dependencies automatically.
- **Develop and contribute extensions**: Use the enhanced `xk6` toolbox for extension development.

  ```bash
  # Create a new extension project from a template
  xk6 new --template=my-extension
  
  # Build and test the extension
  xk6 build --with my-extension=./my-extension
  xk6 test ./tests/
  
  # Check if the extension meets registry specifications
  xk6 lint
  ```

**3. Migrating and Writing Browser Tests**

k6 2.0 significantly improves its browser module's compatibility with the [Playwright](https://playwright.dev/) API. Existing Playwright test scripts can be more easily migrated to k6, leveraging k6's load testing capabilities. Teams can smoothly transition from "does the feature work correctly" verification to "how does the feature perform under high load" performance validation.

**4. Writing Assertion Tests**

Choose between **checks** and **assertions** based on the scenario.

- For static assertions in load tests (such as status codes), use non-retry assertions:

  ```javascript
  import { expect } from 'https://jslib.k6.io/k6-testing/0.6.1/index.js';
  // ... in the default function
  expect(response.status).toBe(200);
  ```

- For browser tests requiring element waits, use auto-retry assertions:

  ```javascript
  import { expect } from 'https://jslib.k6.io/k6-testing/0.6.1/index.js';
  // ... in the browser test function
  await expect(page.locator("#login-button")).toBeVisible();
  ```

**5. Integration and Scalable Deployment**

- **CI/CD integration**: k6 2.0 adds structured JSON summary output, making it easy for CI/CD systems and AI agents to parse test results and make automated decisions.
- **Real-time observability**: Through the native [OpenTelemetry output](https://grafana.com/docs/k6/latest/results-output/real-time/opentelemetry/), k6 performance metrics can be correlated with the application's own APM telemetry data.
- **Production-scale deployment**: Use the stable [k6 Operator](https://grafana.com/blog/2025/09/16/distributed-performance-testing-for-kubernetes-environments-grafana-k6-operator-1-0-is-here/) to run distributed tests in Kubernetes clusters, generating realistic and scalable load.

## SRE Takeaways

- **Reliability and observability connection**: The k6 2.0 updates directly serve the core SRE goal of improving system reliability. AI-accelerated test case generation enables earlier discovery of performance bottlenecks. Integration with OpenTelemetry enables "shift-left" performance observability, allowing performance data obtained during development and testing to seamlessly connect with production monitoring data, forming a complete observability loop. Extension capabilities allow SREs to conduct specialized performance testing against critical infrastructure components like message queues and databases.

- **Best practices and common anti-patterns**:
    - **Best practice**: Use `k6 x agent`-generated tests as a starting point, with engineers reviewing and refining them. Leverage the extension registry to avoid reinventing the wheel, preferring official or community-verified extensions. In load tests, properly distinguish between **checks** (recording metrics) and **assertions** (terminating invalid scenarios). Combine k6 Operator for production-like distributed testing.
    - **Common anti-pattern**: Over-relying on AI-generated tests without human review. Introducing unnecessary extensions for simple scenarios, increasing complexity. Incorrectly using assertions instead of checks in load tests that need to continuously collect error rate metrics.

- **Relevant metrics (SLI/SLO/SLA)**: k6 is an ideal tool for defining and measuring performance **SLIs (Service Level Indicators)**. It can easily measure:
    - Response time (e.g., P95, P99 latency)
    - Throughput (requests per second)
    - Error rate (based on HTTP status codes, `checks`, or `assertions`)

    These metrics are directly used to set performance **SLOs (Service Level Objectives)**, such as "95% of order API response times should be under 200ms." k6's `thresholds` feature can directly verify whether these SLOs are met during testing, making it a key component of automated performance gates (as part of **SLA** enforcement).
