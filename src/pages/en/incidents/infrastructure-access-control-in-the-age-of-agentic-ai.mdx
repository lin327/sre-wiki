# Infrastructure Access Control in the Age of Agentic AI

## Overview

As Agentic AI (AI agents with autonomous reasoning and tool invocation capabilities) moves from experimental environments to production, its role in infrastructure is undergoing a fundamental transformation. Traditional Identity and Access Management (IAM) models are primarily designed around predictable human user access patterns, while AI agents operate very differently. They can dynamically and unpredictably execute operations across services, databases, APIs, and various internal systems. This presents a severe security and operational challenge: how to grant AI agents necessary access permissions while ensuring their behavior is controllable, auditable, and risk is minimized? This article explores the core challenges under this new paradigm and introduces modern solutions centered on [[jit-access]] and [[dynamic-secrets]], such as [[zero-trust]] access proxies, that help SRE teams safely scale Agentic workloads.

## Core Concepts

To address Agentic AI access control challenges, several key concepts and their differences from traditional models must first be understood.

### Agentic AI Identity
Unlike human users or static service accounts, AI agent identities are **dynamic and ephemeral**. An agent may need different access permissions for different tasks (such as troubleshooting, data queries), and each session may involve different combinations of operations. Therefore, a fixed, long-term static role cannot be assigned; instead, a **unique, temporary identity** must be created for each run or task session.

### Just-In-Time (JIT) Access
This is the core principle for handling dynamic identities. Permissions should not be statically assigned at deployment time and retained long-term, but should be **dynamically granted at the time of access, based on identity, task intent, and real-time context**. For AI agents, this means:
- **On-demand permission granting**: Access permissions are only granted when specific tasks need to be executed (e.g., reading specific logs, querying specific databases).
- **Minimum duration**: Permissions are valid only for the current session or task duration. After task completion, session accounts and permissions are immediately revoked.
- **Principle of least privilege**: Strictly limit operations the agent can perform; for example, a troubleshooting agent may be granted read-only permissions without write capabilities.

### Dynamic Credential Injection
To address issues of static credential (e.g., SSH keys, database passwords) leakage, rotation difficulties, and audit challenges, modern solutions employ **credential abstraction** and **dynamic generation**.
- **Credential Injection**: The AI agent itself does not need to know or store any sensitive credentials. When it needs to access a protected resource (e.g., database), the secure access proxy (e.g., [[boundary]]) **directly injects necessary credentials into the session connection** at session establishment time. The agent only communicates with the security proxy; credentials are completely transparent to it.
- **Dynamic Credentials**: Further, integration with secret management tools like [[vault]] enables **real-time generation of ephemeral, one-time credentials** for each session. For example, generating a temporary database user password for a single query that automatically expires after a few minutes. Even if credentials are intercepted, they cannot be reused.

### Session-Aware Control Plane
Traditional network or application-layer gateways are typically insufficient for handling the fine-grained access needs of Agentic workloads. A robust control plane (e.g., [[boundary]]) operates at the **connection/session layer**:
- **Identity-Aware Proxy**: All connection requests from AI agents must pass through this proxy. Before establishing connections, the proxy first verifies the AI agent's identity.
- **Policy Enforcement Point**: Based on the verified identity, its group/role membership, and predefined policies, the proxy decides in real-time whether to allow a session to the target resource.
- **Network Abstraction**: AI agents cannot directly discover or access the underlying network; all access goes through the proxy, effectively limiting the attack surface.

## Practice: Secure Access for Agentic AI with Boundary + Vault

The following illustrates how to use [[boundary]] combined with [[vault]] to provide secure, auditable production environment access for AI agents:

**Step-by-step process:**
1. **Authentication and Identity Assignment**: The AI agent (or user session acting on its behalf) authenticates to [[boundary]]. Boundary creates a unique, temporary agent account (e.g., `acfaria-codex-agent-20260515t175636z`) and associates it with pre-configured roles and policies.
2. **Authorization and Session Establishment**: The agent requests connection to a specific target (e.g., web server `demo-web-server-target`). [[boundary]] verifies whether it is authorized to access that target based on policies. Upon approval, Boundary acts as a proxy to establish an encrypted secure channel (session) between the user/agent and the target.
3. **Credential Injection**: Simultaneously with session establishment, [[boundary]] automatically retrieves or directly injects required dynamic credentials from [[vault]]. For example, when connecting to a database, a temporary database account password generated specifically for that session is used, and the credential is invisible to the AI agent itself.
4. **Operations and Monitoring**: The AI agent executes diagnostic and remediation operations through this secure session (e.g., checking service status, modifying configuration files). All operation commands and output pass through Boundary's proxy channel, enabling complete recording.
5. **Session Recording and Auditing**: [[boundary]] supports session recording functionality. For interactive access like SSH, the entire session text record can be captured for post-hoc review and compliance analysis.
6. **Instant Revocation**: Once the diagnostic or remediation task is complete, the session and its corresponding temporary account and credentials are discarded or destroyed. When executing remediation steps, a completely new session account may be created, ensuring each operation is based on explicit intent and minimum privilege scope.

## SRE Essentials

Incorporating Agentic AI access control into SRE practices requires attention to several aspects:

### Relationship to Reliability, Observability, and Incident Response
- **Enhanced Incident Response**: As shown in the example, AI agents can safely participate in incident diagnosis and initial remediation, greatly accelerating MTTR. The key is that all operations are conducted under strict access control and monitoring, preventing larger-scale failures from agent errors or compromise.
- **Deep Observability**: Through [[boundary]]'s centralized session logs and recordings, SRE teams gain **unprecedented, fine-grained, identity-associated operational observability**. This includes not only "who accessed what at what time" but also "what commands were specifically executed," providing golden data for fault root cause analysis and security investigations.
- **New Dimensions for SLI/SLO/SLA**: In Agentic scenarios, consider adding "AI agent task execution success rate," "average task execution time," or "number of agent-caused misoperations" as new SLIs to measure the reliability and efficiency of AI-assisted operations and set related internal SLOs.

### Best Practices and Common Anti-Patterns
- **Best Practices**:
    1. **Enforce Zero Trust**: Never default-trust any AI agent, regardless of where it originates within the internal network. Strong authentication and real-time authorization are mandatory.
    2. **Adopt Least Privilege and JIT Access**: Configure the strictest roles and policies for AI agents and always use JIT access patterns. Refuse to grant any long-term, broad permissions.
    3. **Prioritize Dynamic Credentials**: Through [[vault]] integration, minimize the use of static credentials. For static credentials that must be used, inject them through proxies to keep them away from agent code and operators.
    4. **Establish Complete Audit Chains**: Ensure all agent activities are associated with their operator's identity, specific task intent, and approval policies, forming traceable audit records.
    5. **Incorporate Agent Session Monitoring into Operations Monitoring**: Add monitoring for abnormal agent session activity (e.g., unexpected time access, high-frequency error attempts) to existing monitoring and alerting systems.

- **Common Anti-Patterns**:
    1. **Using Long-Term Static Credentials**: Configuring fixed SSH keys or database passwords for AI agents and allowing persistent storage. This is one of the biggest security risks.
    2. **Over-Authorization**: For convenience, granting AI agents all permissions they "might need," severely violating the principle of least privilege.
    3. **Lack of Session Isolation and Recording**: Allowing agents to directly execute operations as operations staff, making it impossible to distinguish human from machine behavior and breaking audit trails.
    4. **"Deploy and Forget" Security Configuration**: Configuring permissions once at deployment and never updating, ignoring dynamic policy adjustments and periodic reviews.

### Related Metrics
Beyond traditional availability metrics, when managing Agentic AI access, consider the following SRE-related metrics:
- **Access Authorization Failure Rate**: Frequency of AI agent task failures due to insufficient permissions, useful for evaluating whether policies are too strict or unreasonable.
- **Dynamic Credential Generation Success Rate**: When integrated with [[vault]], the success rate and latency of credential generation/retrieval.
- **Average Session Duration**: Reflects the average execution time of AI agent tasks.
- **Abnormal Session Proportion**: Proportion of sessions flagged as suspicious or triggering alerts, a direct indicator of security risk.

By adopting the above principles and practices, SRE teams can build a modern access management framework that supports efficient Agentic AI operation while ensuring infrastructure security and controllability, truly achieving scaled, production-grade AI-empowered operations.
