# Customize preconfigured views for AWS, Azure, and Google Cloud with Cloud

## Overview

In cloud-native and hybrid cloud environments, effectively monitoring and understanding the status of cloud services (such as AWS RDS, Azure VM, GCP Cloud SQL) is critical for maintaining system reliability. One of the core values of Grafana Cloud's cloud service observability feature is providing out-of-the-box preconfigured dashboards and drill-down views. However, each organization has its specific monitoring priorities, workflows, and established dashboards. This document explains how to customize these preconfigured views in Grafana Cloud to meet specific team monitoring needs, ensuring the most relevant and familiar data perspective is available during troubleshooting and performance optimization.

## Core Concepts

The customization capabilities for cloud service observability in Grafana Cloud revolve around three core concepts, which together allow users to seamlessly integrate personalized workflows while retaining the flexibility of preconfigured views:

1.  **Quick Links and Default Dashboards**: This feature allows you to associate an existing or new Grafana dashboard as a quick entry point for a specific cloud service (e.g., Amazon RDS). By setting it as "default," when users access the service from entry points such as the service list, Entity Graph, or Database Observability, the system will directly display this custom dashboard instead of the preconfigured generic view. This ensures the team always starts analysis from the most familiar interface.
2.  **Instance Drill-Down View**: When users drill down from a service overview to a single instance (e.g., a specific RDS instance or Lambda function), the system displays the instance drill-down view. This view consists of a set of predefined metric panels and queries. You can customize this view to control which specific metrics are displayed at this level, how queries are organized, and the layout and units of panels. This configuration takes effect uniformly across the entire Grafana Cloud ecosystem (including cloud service observability, database observability, and Entity Graph), ensuring consistency in the analysis path.
3.  **AI-Generated Dashboards**: For scenarios where you want to quickly obtain dashboards conforming to industry best practices (such as RED/USE methodology) without building from scratch, you can use AI-generated dashboards. This feature creates a starting-point dashboard with correct variables and panels, which users can then adjust and add to service links like a regular custom dashboard, or even set as the default view.

## Practice

All customization operations for cloud services are centralized on that service's "Configure" page. In Grafana Cloud's "Services" tab, click **Configure** next to the target service to enter.

### 1. Connecting an Existing Dashboard

If you already have a mature dashboard for a specific cloud service (e.g., an RDS monitoring panel built by an internal operations team), you can add it as a quick link for that service.
1.  On the service's configuration page, find the "Customize your quick links and add new custom dashboards" section.
2.  In the "Select dashboard" dropdown menu, select the target dashboard from your Grafana stack, then click **Add**.
3.  The newly added dashboard will appear in the list. Click **Set as default** next to it to set it as the main view. Click **Save** to save the configuration.
4.  Going forward, this custom dashboard will appear as a quick link at the top of the service page. If it is the default view, it will become the primary interface for all entry points into that service within the application.

### 2. Creating and Linking a Dashboard Using AI

If there is no existing dashboard, you can quickly generate a basic version through AI.
1.  On the same service's configuration page, in the "Customize your quick links..." section, click **Generate with AI**.
2.  The AI will generate a dashboard containing metrics related to that service, correct variables, and standardized panels (following RED/USE methodology). You can preview and save it.
3.  After saving, you can return to the configuration page via the link provided by Grafana Assistant.
4.  Select the just-generated dashboard in "Select dashboard," click **Add**, set it as default if needed, and finally click **Save**. This AI-generated dashboard is now integrated into the service workflow and can be edited at any time.

### 3. Editing the Instance Drill-Down View

This operation will uniformly modify the view displayed when clicking any single cloud resource instance.
1.  On the service's configuration page, scroll to the "Customize panels that will appear in the instance drill-down view" section.
2.  Toggle the switch to enable custom panels.
3.  In the available metrics/query selection list, you can search, select all/deselect, or add custom queries. Specify the panel to associate with each query.
4.  In the panel grid area, you can drag panels to reorder, edit titles, modify units, adjust legend format and aggregation method for each query. You can also move queries between panels or create new panels.
5.  After completing all adjustments, click **Save**.

Once the configuration takes effect, whether navigating to the instance from cloud service observability, database observability, Entity Graph, or alert details page, your customized drill-down view will be displayed.

## SRE Key Points

- **Reliability and Incident Response Association**: Customized views directly serve SRE's core practices—quickly identifying problems (MTTD) and recovering services (MTTR). When an alert triggers, responders can immediately enter their trusted default dashboard containing key diagnostic metrics, rather than spending time finding the correct data in a generic view. The unified instance drill-down view ensures that critical context and metrics are not lost when drilling down from macro service monitoring to micro instance diagnosis, greatly improving troubleshooting efficiency.
- **Best Practices and Anti-Patterns**:
    - **Best Practices**: Set default custom dashboards for the team's most frequently monitored core services; ensure instance drill-down views contain the most relevant error, latency, and resource utilization (RED/USE) metrics; use AI generation as a starting draft, then customize based on business logic.
    - **Common Anti-Patterns**: Setting the same default dashboard for all services, ignoring service-specific characteristics; over-customizing instance views leading to information overload; not reaching team consensus on the content of "default views" and "drill-down views."
- **Related Metrics (SLI/SLO)**: The core purpose of custom dashboards is to display **SLIs** more precisely. For example, for web services, customized views may highlight P99 latency and error rate SLIs; for databases, they may focus more on query latency and connection count SLIs. By placing key SLIs in the most prominent positions in the view, corresponding **SLOs** can be measured and managed more intuitively, and correlated with **Error Budget** consumption.

By fully leveraging Grafana Cloud's cloud service observability customization features, SRE teams can build an observability system that is both standardized and personalized, both globally unified and rich in detail, thereby more confidently ensuring the reliability of cloud services.
