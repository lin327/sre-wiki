## Overview

In Grafana panels, the `Mixed` data source is a powerful tool that allows multiple different data sources to be combined within the same panel, or to reference data from other panels within the same dashboard through the `--Dashboard --` ("Other Panels") data source. However, there is a known flaw that breaks this flexibility: when a `Mixed` panel references two or more `--Dashboard --` panels, and **time shift** (Time shift or Relative time) is set for these queries, the panel will be permanently stuck in the loading state (the circle animation continues), unable to render data. This is a critical UI flaw that affects the usability of monitoring panels and is directly related to the reliability of custom dashboards that SRE teams rely on.

## Core concepts

1. **Mixed Data Source**: A Grafana data source type that does not produce data itself, but acts as a proxy, forwarding queries to one or more other configured data sources. It can be used to aggregate data from Prometheus, SQL database and another panel in a single panel.
2. **`-- Dashboard --` Data source (Other Panels)**: A special option provided by `Mixed` data source. It allows queries for the current panel to directly reference and obtain processed result data from some other panel within the same dashboard (called the "source panel") without having to re-issue the query to the backend data source. This is often used to create "chained panels" or data summary panels.
3. **Time Override**: In the "Query Options" of the panel, you can set a time offset (Time shift, such as `1h`) or a fixed relative time (Relative time, such as `now-1h`) that is independent of the global time range for each query. This function is used to compare data from different time periods.
4. **Essence of the problem**: This defect occurs in the front-end rendering layer. According to the issue report, the underlying data query actually executed successfully and returned data, but Grafana's front-end UI logic was unable to properly handle the scenario of "multiple dashboard data source queries" combined with "time overlay", causing the rendering loop to fail to complete and the panel to behave as if the data was forever loading.

## Practice

### Steps to reproduce the problem

The following steps describe exactly how to trigger this issue:

1. **Create Source Panel**: In any dashboard, create a panel that uses any data source (such as the `Random Walk` sequence of the TestData data source). This panel will act as the data provider.
2. **Create Chained Panel (Triggered Panel)**: Add a new panel in the same dashboard and set its data source to **`Mixed`**.
3. **Configure multiple dashboard queries**: In the `Mixed` data source panel, add at least **two** queries. Select the data source of each query as **`-- Dashboard --`**, and in the "Panel" option below, point to the source panel created in step 1.
4. **Set time override**: In the Query Options area of ​​the chained panel, enable **Time shift** (e.g. `1h`) or **Relative time** (e.g. `now-6h` to `now-3h`) for any or all of the queries. Alternatively, you can go back and set the time override for the source panel itself.
5. **Observe the phenomenon**: Save and refresh the dashboard. Chained panels will have a constant loading indicator (spinning circle) and will never be able to display chart data. If you reduce the number of panel queries to **one**, or **remove** all time override settings, the panel will render normally immediately.

### Version information

This issue affects **Grafana v11.6.x, v12.4.x and v13.0.2**. According to the issue tracker, the flaw was introduced in PR #124665.

### Current situation and avoidance

This is a confirmed front-end flaw. Until an official fix is released, SRE teams must take workarounds:

* **Avoid using combinations**: **Never** mix **multiple `--Dashboard --` queries** and **time overrides** in the same `Mixed` data source panel.
* **Alternative 1**: If you need to compare time offsets of data from different panels, consider configuring them in separate panels, or use other data sources that support this feature (such as Prometheus's `offset`) to directly query the original data.
* **Alternative 2**: If you must use `Mixed` with dashboard queries, ensure that each `Mixed` panel contains only **one** `--Dashboard--` query.

## SRE Key Points

* **Impact on Reliability**: This issue directly breaks the **usability** of Grafana dashboards. Monitoring views that rely on such complex chained panels will be completely ineffective, preventing the SRE team from obtaining critical operational insights, which may affect the judgment of system status and the speed of incident response.
* **Observability Correlation**: Grafana is the core UI component for building an observability platform. Such UI rendering flaws can "mask" the actual availability of backend data (the data has been returned), creating "observability blind spots" where the data exists but cannot be viewed.
* **Best Practices and Anti-Patterns**:
    * **Anti-Pattern**: Design overly complex panel data dependencies. Aggregating multiple panel results through `--Dashboard --` and then applying time overlay is currently a high-risk mode for triggering known flaws.
    * **Best Practice**: "Simplicity Principle" for monitoring configuration. For critical monitoring panels, simpler and more stable data streams should be prioritized. Before upgrading your Grafana version, complex dashboard functionality should be verified in a test environment.
* **Related Metrics**: While this issue does not directly affect the calculation of SLI/SLO (since the underlying data query succeeds), it affects the reliability of the tools used to **present** these metrics. Therefore, the UI functional integrity of the monitoring panel (for example, whether it renders properly) should be considered one of the health indicators of the monitoring infrastructure itself.
