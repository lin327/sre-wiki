## Overview

In SRE practice, visual dashboards are a core tool for monitoring system health and quickly diagnosing problems. As a mainstream observability platform, Grafana's data transformation (Transformation) function allows complex reorganization of query results to generate the required views. However, when the conversion logic fails to handle correctly when the data source returns a null result, the panel prompt information will be misleading, thereby affecting the SRE's quick and accurate judgment of the system status. Based on a specific case, this article analyzes the problem of abnormal prompt information in the no-data state when using "rows to fields" conversion and its potential impact on reliability.

## Core concepts

**"rows to fields" transformation**: This is a data transformation function provided by Grafana. Its core function is to remap or group row data in the data set into new fields. SREs often use this feature to structurally reorganize raw bar data from logs, tracking, or monitoring to fit specific visualization types such as pie charts and bar charts.

**No data state for dashboards**: When a data source query returns no results within a given time range, a Grafana panel should enter a "No data" state. This is a clear and expected status, prompting the user that the current monitoring indicators have no value or the query conditions are too strict, rather than a system failure.

**The difference between "Cannot visualize data" and "No data"**: In the context of Grafana, "No data" is a standard status prompt indicating that the query was successful but the result set was empty. "Cannot visualize data" is usually a warning or error message, which may imply that there is a problem with the data format, the conversion logic fails, or the data structure does not match the visualization requirements. Misusing the latter with the former can obscure the source of the problem and increase the complexity of troubleshooting.

## Practice

According to the issue report, the steps to reproduce this issue are as follows:
1. **Prepare data**: Obtain a data set containing field (column) definitions but without any row data. This simulates a scenario where no events or indicators are reported within a certain time window in the monitoring system.
2. **Apply Transformation**: In the "Transformations" tab of the Grafana panel, add the "rows to fields" transformation.
3. **Configure Transformation**: In the transformation settings, manually specify a field name.
4. **Observation results**: When the query returns empty results, the panel should display the "No data" status, but what is actually observed is the "Cannot visualize data" warning prompt.

**Expectations vs. Actual Behavior**:
* **Expectation**: The panel displays a clear, standardized "No data" status, as shown in the screenshot from the question. This allows users to immediately understand that there is currently no data and to further examine the query or data source.
* **Actual (current behavior)**: Show "Cannot visualize data" warning. This falsely suggests a problem with the visualization process or data structure, leading the user to incorrectly examine the transformation configuration rather than the query itself or data source status.

This issue occurs in Grafana version 11.6.1 and behaves normally in version 11.5.4, indicating that this is a regression flaw introduced by a version update. The issue is not limited to pie charts and may affect all visualizations that use the "rows to fields" transformation and may return empty data.

## SRE Key Points

* **Impact on Reliability**: Dashboards are the first line of defense for SRE observability. The accuracy of prompt information directly affects Mean Time to Acknowledge (MTTA) and Mean Time to Resolve (MTTR). A misleading prompt can cause SRE engineers to waste time in the wrong troubleshooting direction (such as checking the conversion configuration) while ignoring the more fundamental cause (such as data collection interruption).
* **Best Practices and Anti-Patterns**:
    * **Best Practice**: All data visualization tools should follow the principle of "clearer than smarter" and provide clear and consistent user interface feedback for predictable states (such as no data). Monitoring dashboards should be treated as “code” and their behavior should be subject to version control and regression testing.
    * **Anti-Pattern**: The external user-visible status prompt is inadvertently changed due to changes in internal error handling logic. This violates the principle that observability tools should provide stable and predictable interaction interfaces.
* **Related indicators (SLI/SLO/SLA)**:
    * **SLI (Service Level Indicator)**: For the monitoring platform itself, you can define "dashboard data correctness" SLI. For example, monitor panels that use "rows to fields" and other transformations. When the data source returns empty, the proportion of "No data" status appears.
    * **SLO (Service Level Objective)**: You can set goals, such as "When the data source returns empty results, 99% of the panels should correctly display the 'No data' status within 2 seconds."
    * **Associated Impact**: Although this flaw is small, if it occurs on a key business monitoring dashboard, it may indirectly affect the timeliness and accuracy of the **Availability** SLO alarm judgment of downstream services.
