# 

## Overview

Grafana QueryField is the core interactive editor for users to build queries (such as PromQL, LogQL, Splunk queries, etc.). Its auto-completion feature is designed to improve the efficiency of query writing, using contextual hints for variables, functions, etc. However, a reported bug causes some text fragments in queries to be accidentally deleted when using autocompletion (specifically variable completion). For SRE teams that rely on Grafana for daily monitoring and troubleshooting, such interaction flaws at the UI layer will directly interfere with work efficiency, and may even lead to incorrect queries or dashboard configurations due to misoperation.

## Core concepts

- **QueryField**: Rich text editor component in Grafana for writing and editing data source queries. It is built based on the Slate.js framework and integrates syntax highlighting, auto-completion and other intelligent functions.
- **Autocomplete (Autocomplete)**: A list of prompts triggered when typing in QueryField, helping users quickly complete query language keywords, functions, variables (such as `$variable`), etc.
- **SuggestionPlugin**: A plug-in in Grafana QueryField that manages the triggering, acquisition and display logic of auto-completion suggestions. According to the information in the Issue, the root cause of this problem is pointed to the processing logic of the plug-in.
- **Variable**: A function used in Grafana to animate dashboards, allowing users to define template variables that can be referenced in queries. Typing `$` into a QueryField usually triggers autocompletion of the variable list.

## Practice

### Problem recurrence

1. Create a dashboard in Grafana that contains template variables.
2. Start writing a query in the QueryField editor, for example `index=my_index host=$host` using the Splunk data source.
3. After typing the `$` symbol, wait or manually trigger the autocomplete list.
4. Select a variable from the list (such as `$host`) for completion.
5. **Expected Behavior**: The query becomes `index=my_index host=$host`.
6. **Actual Behavior (Bug)**: The query may incorrectly become `index=my_index host=`, losing part of the previously entered query content.

### Impact and temporary solutions

- **Impact**: Mainly affects users who rely on variables for dynamic queries, especially those complex query scenarios using data sources such as Splunk. Bugs will cause users to repeatedly check and correct queries, seriously reducing work efficiency.
- **Temporary solution**:
    - **Manual input**: When the variable value is known, temporarily avoid using automatic completion and enter the query string manually instead.
    - **Use template**: For highly repetitive queries, you can write them in a text editor first, and then copy and paste them into QueryField.
    - **FOLLOW OFFICIAL FIX**: Keep an eye on the progress of this GitHub Issue (#79856) and upgrade to a Grafana version that includes the fix.

## SRE Key Points

- **Impact on Reliability**: Although this bug does not directly cause data loss or service interruption, it destroys the interaction reliability of the core tool (Grafana). SRE teams rely on accurate and efficient UI to quickly build dashboards and alerting rules, and such defects introduce friction and extend the MTTR (mean time to repair) of troubleshooting.
- **Link to Observability**: Grafana is a key interface for building an observability platform. QueryField problems directly hinder users from effectively querying and visualizing monitoring data (Metrics, Logs), weakening the overall observability capabilities.
- **Best Practices**:
    - **KEEP TOOLS UPDATED**: Track and apply stable version updates of Grafana promptly for important bug fixes.
    - **Establish internal feedback channels**: When the SRE team encounters tool defects that affect work efficiency, it should be reported promptly within the team or through official channels (such as GitHub Issues) to promote problem resolution.
    - **Key Operation Verification**: When relying on intelligent features such as auto-completion to construct key queries or alerts, the final generated query string should be carefully checked to ensure that it is correct.
- **Common anti-patterns**:
    - **Over-reliance on the interactive function of a single tool**: Relying entirely on the automatic completion of the UI for complex queries without understanding the underlying query syntax itself will make it impossible to work effectively once the UI goes wrong.
    - **Ignore known bugs**: Even after knowing clearly that there is a bug that affects work efficiency, you still do not seek workarounds or push for fixes, and continue to tolerate inefficient workflows.
- **Related indicators**: This issue mainly affects user satisfaction (USAT) and development/operation and maintenance efficiency, and indirectly affects related indicators of service stability (such as MTTD, MTTR), but cannot be directly measured by SLO/SLI.
