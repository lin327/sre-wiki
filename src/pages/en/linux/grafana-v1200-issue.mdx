# Grafana v12.0.0 重复行刷新问题 Issue

## Overview

In the daily operation and maintenance of SRE, the Grafana dashboard is the core tool to achieve system observability. A dashboard that can dynamically filter and display data based on variables (such as `region`, `service`) is crucial for quickly locating problems and conducting multi-dimensional analysis. The Row Repeat function allows the dashboard to automatically copy the entire row and its internal panels based on variable values, greatly improving the flexibility and information density of the dashboard. However, a flaw discovered in Grafana v12.0.0 will cause the repeatedly generated panel data of the first row to not be refreshed when variables are changed, only the title will be updated. This directly destroys the real-time and reliability of data display and may mislead SRE in fault judgment.

## Core concepts

- **Variable**: In Grafana dashboards, variables are dynamic values that users can select at the top of the dashboard, often used to filter data. Supports single-value and multi-value selection.
- **Row Repeat**: A feature of the dashboard that allows configuring a row to automatically replicate based on multiple selected values ​​of a variable. For example, if the variable `region` selects `us-east` and `eu-west`, then the row will be copied twice, corresponding to the two regions.
- **Panel Repeat**: Similar to row repeat, but the unit of repetition is a single panel within the row.
- **Data Refresh**: When the status of the dashboard (such as variable selection) changes, Grafana re-initiates the query to the back-end data source and updates the panel visualization results.

Specifically: when row duplication is enabled and panel duplication is disabled, variable changes cause new rows to be created and queries to be executed, but the first rendered row only updates the title text of its panels, without triggering new data queries for those panels.

## Practice

### Steps to reproduce the problem

According to reports, this issue is reproducible stably in Grafana v12.0.0:

1. **Create multi-value variable**: Create a variable (e.g. `region`) in the dashboard settings and configure it to support selecting multiple values.
2. **Configure repeating rows**: Create a dashboard row and enable its "repeat" option, set to repeat based on the variable (`region`) created in step 1.
3. **Add Panel**: Add one or more panels within the row and reference the variable in its data query statement.
4. **Change Variable**: In the dashboard variable selector, select multiple values ​​for the `region` variable.
5. **Observation**: At this point, the dashboard should generate a duplicate row for each selected value. The newly generated rows will execute the data query normally and display the results, but the **first row** (i.e. the initial row) only refreshes the panel title and its data content (charts, tables, etc.) remains unchanged. You must manually click the "Refresh" button at the top of the dashboard for the first row of data to update correctly.

A reproducible test dashboard has been provided by the reporter in [Grafana Play](https://play.grafana.org/d/fefps6n1het4wc/wip-2024?orgId=1&from=now-6h&to=now&timezone=utc&var-region=%24__all&var-role=%24__all&var-size=5%2C001%2B%20employees).

### Impact on SRE workflow

This issue directly affects the SRE's monitoring and troubleshooting processes. In scenarios that rely on dynamic row duplication to compare performance across services, clusters, or regions, SREs may misjudge by seeing stale first rows of data. For example, when the `region` variable switches from `us-east` to `us-west,eu-west`, the SRE expects to see the latest metrics for all selected regions. If the first row (which may still show old data for `us-east`) is not refreshed, it may mask severe performance degradation in a region.

## SRE Key Points

### Association with reliability, observability, incident response

- **Observability**: This bug directly reduces the real-time and accuracy of dashboard data. In incident response, outdated data can be fatal and can lead to misdirected root cause analysis.
- **Incident Response**: After an alarm is triggered, the SRE will immediately check the relevant dashboard. If the first row of data becomes stale due to the row duplication feature, identification of critical issues may be delayed.
- **System Reliability**: As the output of the monitoring system, the reliability of the dashboard is the basis for the credibility of the entire observability system. Weaknesses in such interface layers can reduce a team's trust in the overall monitoring system.

### Best practices and common anti-patterns

- **Best Practices**:
    1. **Verification Verification**: After upgrading the Grafana core version, especially the version involving dashboard rendering and variable logic, regression testing of complex duplicate dashboards should be performed in a test environment.
    2. **Alternative**: Before the official fix, you can temporarily avoid using the "row duplication" function. For scenarios that require multiple value comparisons, consider using the Panel Repeat feature, or creating multiple dashboards with fixed values ​​for different variables.
    3. **Monitor the dashboard itself**: Incorporate monitoring into the availability and data freshness of key business dashboards. For example, query dashboard status via the `grafana_api` data source, or use synthetic monitoring to simulate user interactions.
- **Common anti-patterns**:
    - **Blind reliance on new features**: Using complex features from the latest version that have not been fully tested (such as line duplication in v12.0.0) directly in production.
    - **Ignore refresh mechanism**: In automated workflows or critical alert processes, rely on a potentially unstable automatic refresh mechanism without verifying its effect.

### Related Indicators (SLI/SLO/SLA)

While this issue itself does not directly correspond to the SLI of an external service, it profoundly affects the reliability metrics of internal monitoring tools:

- **Internal SLI**: You can define "variable change data refresh success rate of key dashboards (such as core business SLO dashboards)" as an internal SLI to monitor whether its actual refresh behavior after variable changes meets expectations.
- **Tool Availability**: Dashboard functionality failure can be considered a "partial unavailability" of internal monitoring tools, impacting the productivity and confidence of the SRE team.

It is recommended to pay attention to Grafana's official follow-up to this issue, and fully consider the stability of such front-end rendering logic when upgrading or adjusting the architecture.
