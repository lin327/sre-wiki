## Overview

In the Grafana observability platform, the `Legend` option of the chart panel is used to configure the display format of the legend. Template variables such as `{{namespace}}/{{pod}}` are often used to dynamically display identification information. This document describes a known UI display flaw: slash (`/`) symbols in the legend configuration are incorrectly rendered as HTML entity encoding (`&#x2f;`) when the chart panel is collapsed, but appear fine when the panel is expanded. While this is a display flaw on the front end, in SRE practice, the accuracy and consistency of monitoring dashboard information is critical for rapid diagnosis and incident response. Any display errors that could mislead operations staff, even subtle ones, could interfere with immediate understanding of service topology or resource paths and therefore need to be identified, understood and, if necessary, fixed.

## Core concepts

This question involves the intersection of several key technical concepts:

1. **HTML entity escaping**: In order to display special characters safely in HTML documents, the browser or framework will convert certain characters into the corresponding entity encoding. For example, the slash `/` has the entity form `&#x2f;` or `&frasl;`. The problem is that the UI component incorrectly applies escaping logic in a context where escaping should not occur.
2. **Front-end state management**: Grafana is built by front-end frameworks such as React. The "collapse" and "expanded" of the panel represent two different UI states. This bug indicates that when handling the rendering logic in the collapsed state of the panel, the function used to generate the legend display string may be using a different rendering pipeline or escaping strategy than in the expanded state.
3. **Template variable rendering**: In Grafana, `{{variable}}` is a template variable. The rendering engine needs to parse variables (such as `{{namespace}}` and `{{pod}}`) into actual values ​​before processing normal text between them (such as `/`). This bug indicates that the parsed string is improperly subjected to an additional HTML encoding before being finally output to the collapsed UI component.

## Practice

### Steps to reproduce the problem

1. **Configure legend**: Edit a chart panel in Grafana, enter the `Options` panel, and find the `Legend` configuration item.
2. **Set format containing slashes**: Set the value of Legend to a template string containing slashes, for example: `{{namespace}}/{{pod}}`.
3. **Collapse Panel**: Collapse the options area of ​​the chart panel (or collapse the entire panel depending on the specific version).
4. **Observe exception**: View the legend text previewed or displayed in the folded state. You will find that slashes `/` appear as `&#x2f;`, for example as `my-namespace&#x2f;my-pod` instead of the expected `my-namespace/my-pod`.

### Root cause analysis

Based on the phenomenon, the root cause is likely to be that in the Grafana front-end code, the component responsible for rendering summary information (including Legend configuration preview) when the panel is folded/collapsed performed unnecessary HTML entity escaping on the rendering string. The main rendering component used when the panel is expanded does not do this, or uses a different "safe" rendering method (such as React's `textContent` instead of `innerHTML`), resulting in inconsistent behavior. This is a typical UI consistency problem caused by the out-of-synchronization of front-end state and rendering logic.

### Possible solutions and workarounds

* **Fundamental Fix**: The Grafana development team needs to review and unify the rendering logic of the Legend string to ensure that special characters are treated consistently in both collapsed and expanded view states. In general, for plain text display, avoid using output methods that trigger HTML escaping.
* **User circumvention method**: Currently, this issue only affects the display in the collapsed state and does not affect the actual content and query logic of the chart legend. Therefore, it is mainly a visual distraction. SRE personnel can:
    1. **Keep Panels Expanded**: If this display error is really interfering with your workflow, you can temporarily set the relevant panels to an expanded state.
    2. **Adjust the legend format**: If you must rely on the collapsed view, you can temporarily modify the Legend format to avoid using slashes, such as using dot `.` or dash `-` as the separator: `{{namespace}}.{{pod}}`.

## SRE Key Points

### Association with reliability

* **Observability Accuracy**: Monitoring dashboards are the SRE’s primary window into system status. Any display error, no matter how small, can introduce noise, reducing the signal-to-noise ratio of the information and thus affecting the rapid judgment of the achievement of the service **SLO** (Service Level Objective). An incorrectly displayed path can waste valuable troubleshooting time during incident response.
* **Toolchain Trustworthiness**: Frequent small UI flaws can erode SREs' trust in the monitoring tool itself. A reliable, consistent interface is the foundation of effective operations.

### Best Practices and Anti-Patterns

* **Best Practice**: When developing and testing custom Grafana dashboards or plugins, you should verify that panels render consistently in different UI states (collapse/expanded, fullscreen/grid). Similar cross-state checks should be done for standard dashboards provided to teams for use.
* **Anti-Pattern**: Ignore "small" display issues in monitoring tools. These issues can be magnified and become distractions during stressful troubleshooting moments. Mechanisms should be established to encourage team members to report such issues and provide feedback to upstream projects.

### Related Indicators (SLI/SLO)

This issue itself does not directly affect the SLI (Service Level Indicators) the system is running on, as it does not change the querying and calculation of the underlying metric data. It affects the rendering layer SLI of observability data, such as "Dashboard Key Information Rendering Accuracy". In a broader SRE practice, a goal could be set: the UI for all key monitoring panels should render information with 100% accuracy during primary interaction states. Such bugs are a deviation from that goal.
