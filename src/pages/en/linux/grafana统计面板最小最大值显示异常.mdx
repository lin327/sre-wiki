## 概述

在使用 Grafana 进行可观测性实践时，统计类面板（如 Stat Panel）常用于在仪表盘中醒目地展示关键指标的汇总值，例如 API 响应时间的最小值（Min）和最大值（Max）。这些汇总值对于快速评估系统性能、识别异常波动至关重要。然而，用户有时会观察到，即使在存在请求数据的时间段内，面板上的最小值或最大值统计项也可能显示为空。本文档旨在分析这一问题的可能原因，并提供系统性的排查与实践指南，以确保监控数据的可靠呈现，这是 SRE 维护系统可靠性的基础。

## 核心概念

理解此问题需要把握以下核心概念：

1.  **聚合计算与数据点对齐**：Grafana 面板展示的最小值/最大值，是基于数据源（如 Prometheus, InfluxDB）在给定时间范围内返回的 **一系列数据点** 进行计算得出的。如果查询返回的数据点集合在某个时间点上为空（即无数据），那么基于该集合的聚合计算结果（Min/Max）就无法生成，从而可能显示为空。
2.  **数据稀疏性与降采样（Downsampling）**：当监控指标（如 API 响应时间）本身数据点稀疏，或者查询的时间范围过长、数据源配置了自动降采样时，Grafana 或数据源为了性能，可能不会返回所有原始数据点。这可能导致计算最小值/最大值时依赖的数据点不足或缺失，尤其是在时间范围的边界或数据低谷期。
3.  **时间戳对齐问题**：查询的时间范围（`timeRange`）与数据源中实际数据的时间戳未能精确对齐，也可能导致在某些特定的时间窗口内查询不到数据点，进而使得聚合结果为空。

## 实践

针对“最小值/最大值显示为空”的问题，可以遵循以下步骤进行排查和定位：

**1. 验证原始查询数据**
   - 在面板编辑器中，切换到“Explore”视图，直接执行面板使用的查询语句。
   - 检查返回的时间序列数据，确认在出现空值的对应时间段内，是否确实有数据点返回。这是最直接的验证方法。

**2. 检查查询与数据源配置**
   - **查询范围**：确保查询的时间范围（`Relative time range`）正确覆盖了您期望看到数据的时间段。
   - **数据间隔（Step）**：检查查询的 `Step` 或数据源的采集间隔设置。对于稀疏指标，过大的 Step 可能导致数据点被“跳过”。
   - **数据源健康状况**：确认数据源连接正常，且数据库或存储服务本身在问题时间段内运行正常，有原始数据写入。

**3. 分析面板可视化设置**
   - 检查统计面板的“Null Value”设置。该选项控制当聚合结果为 `null`（无数据）时的显示行为（如显示为 `null`、`0` 或保持空白）。将其设置为 `connected` 或 `null` 有助于区分“值为0”和“无数据”。
   - 确认面板的“Stat”配置项中，`Min` 和 `Max` 已被勾选并启用了显示。

**4. 利用 Grafana 内部监控**
   - Grafana 本身提供了关于查询性能和数据获取情况的指标（如 `grafana_data_source_query_duration_seconds`）。可以通过查询这些内部指标来判断是否在特定时间段发生了查询超时或错误。

**5. 复现与对比**
   - 尝试在一个新建的、干净的测试仪表盘上，使用相同的数据源和查询，观察是否复现。这有助于排除是某个特定仪表盘配置（如变量、模板）引起的问题。
   - 缩短查询的时间范围（例如从 24 小时缩短到 1 小时），观察问题是否消失。如果问题在短时间范围内不出现，则强烈暗示与数据稀疏性或长周期降采样有关。

## SRE 要点

### 与可靠性、可观测性、事件响应的关联
- **可观测性质量**：监控面板是系统可观测性的前端界面。显示异常（如空的统计数据）会直接降低仪表盘的可信度，可能导致 SRE 或开发者在故障排查时产生误判（例如，误以为系统在某段时间完全无流量）。
- **事件响应效率**：在故障发生时，依赖 Min/Max 等统计值可以快速定位性能瓶颈（如响应时间飙升）。数据不显示会延长事件响应的初步诊断时间。
- **监控系统自身的可靠性**：此问题体现了监控管道（从数据采集、存储到可视化）的可靠性挑战。SRE 需要像保障业务系统一样，保障监控系统的可靠性和数据完整性。

### 最佳实践与常见反模式
- **最佳实践**：
  1.  **交叉验证**：对于关键统计值，不要依赖单一视图。同时查看原始时序图（Time Series Panel），可以直观验证最小值和最大值是否符合预期。
  2.  **设置合理的SLO**：为关键 API 的响应时间设置 [[slo]]（服务水平目标），并将 Min/Max 作为 [[sli]]（服务水平指标）的补充观察角度，而不是唯一依据。
  3.  **监控监控系统**：利用 Grafana 自身的监控能力，为重要的仪表盘查询设置告警（如查询持续返回空值）。
- **常见反模式**：
  1.  **盲目信任面板数据**：不验证直接将面板上的统计数据作为决策的唯一依据，尤其是在进行容量规划或性能归因分析时。
  2.  **忽略数据稀疏性**：对于非连续发生的事件型指标（如错误计数），试图用最小值/最大值来描述其特性，这通常没有意义。
  3.  **配置复杂查询未测试**：在生产环境部署包含复杂逻辑或长时间范围的查询前，未在开发环境充分测试其在不同数据密度下的表现。

### 相关指标（SLI/SLO/SLA）
- 此问题本身不直接定义新的 SLI/SLO，但它影响了现有 SLI 的可观测性。例如，如果 SLI 是“P99 响应时间”，而用来查看该指标的统计面板因数据问题而失效，则 SLI 的监控就失去了意义。因此，确保监控仪表盘的稳健性是实现 [[slo]] 的隐性前提。
