# Terraform adds cost visibility, project-level notifications, and more

## Overview

HashiCorp has introduced a series of important updates to its HCP Terraform and Terraform Enterprise platforms. The core goal of these feature upgrades is to eliminate "blind spots" in infrastructure management, thereby strengthening governance, security, and cost control throughout the infrastructure lifecycle. For teams practicing Site Reliability Engineering (SRE), these updates directly relate to key areas such as cost efficiency, system reliability, security compliance, and operational automation, helping to build a more reliable, secure, and efficient infrastructure management system.

## Core Concepts

The core of this update revolves around the **Project** management unit, building more granular governance and isolation boundaries, and introducing deeper observability and security mechanisms.

### 1. Billable Resource Analytics
This feature addresses the pain point of cost opacity under the Resource Unit Management (RUM) billing model. It allows administrators to view resource consumption details at the **Project** and **Workspace** levels, rather than only at the organization total. This enables cost showback/chargeback and resource optimization.

### 2. Project-Level Remote State Sharing
This feature leverages projects as natural isolation boundaries. When a workspace enables the "Share with all workspaces in this project" option, its Terraform state file becomes automatically visible only to other workspaces within the **same project**. This achieves dynamic, policy-based state sharing, avoiding the risks of global sharing and the tedium of manually maintaining access lists.

### 3. Project-Level Notification
This is an implementation of "monitoring-by-default." Notifications configured at the project level (such as Slack, PagerDuty, Email) automatically inherit to all workspaces under it. Any environment newly created or moved into the workspace is automatically monitored, ensuring no "silent failures."

### 4. Module Testing for Dynamic Credentials
This feature extends the use of OIDC (OpenID Connect) dynamic credentials from the standard `terraform plan/apply` flow to the `terraform test` flow. Module tests can now securely use temporary credentials, eliminating the reliance on static "test-only" keys, thereby unifying security authentication policies between testing and production deployment.

### 5. Registry Tagging
This feature (currently in Beta) allows adding key-value pair tags to registry artifacts such as modules and providers—for example, environment tags (`non-prod`, `prod`) or project tags. This provides consumers with clear version status and usage guidance, facilitating quick discovery and selection of appropriate artifacts in complex module ecosystems.

## Practice

The following are typical scenarios and configuration paths for enabling and using these new features in HCP Terraform/Terraform Enterprise.

### Implementing Cost Visibility
Any paying HCP Terraform user can access the new analytics view on the organization's **Usage** page. Administrators can view the number of billable managed resources for the current period by project and workspace, used for analyzing cost distribution and identifying optimization opportunities.

### Configuring Project-Level State Sharing
1.  Navigate to the target workspace's **Settings** > **General**.
2.  Find the **Remote State Sharing** section.
3.  Select the option **"Share with all workspaces in this project"** and save.
After this, other workspaces within this project can access this state via the `terraform_remote_state` data source. **Best Practice**: Prioritize using the more secure [`tfe_outputs` data source](https://registry.terraform.io/providers/hashicorp/tfe/latest/docs/data-sources/outputs) to access output values.

### Establishing Standardized Project-Level Notifications
1.  Navigate to a project's (e.g., `prod` project) **Settings** > **Notifications**.
2.  Add and configure the desired notification destinations (such as PagerDuty integration, Slack Webhook) and triggers (such as run failures).
3.  After saving, all existing and future workspaces under this project will automatically inherit these alert configurations.

### Enabling Dynamic Credentials in Module Testing
1.  Ensure the workspace running `terraform test` is configured for **dynamic credentials** (e.g., OIDC trust relationship is configured).
2.  Update module test files (`*_test.tf`) to use the default authentication method in the cloud provider or HCP Vault configuration block (without specifying static credentials).
When tests run, the framework will automatically exchange OIDC tokens for temporary credentials.

### Tagging Registry Artifacts
1.  In HCP Terraform's registry interface, navigate to the specific module or provider version.
2.  Use the **Tags** feature to add tags, such as `environment: non-prod`.
3.  After thorough testing, update the tag to `environment: prod` to clearly indicate it is ready for production use.

## SRE Key Points

These features directly enhance SRE capabilities in cost, reliability, security, and efficiency.

- **Cost Management and SLO**: **Billable Resource Analytics** provides granular measurement (SLI) of infrastructure costs, forming the basis for establishing and tracking **infrastructure cost SLO/SLA**. It enables SRE to collaborate with finance teams for data-driven capacity planning and cost optimization, avoiding resource waste, and channeling saved resources into reliability improvements related to the Error Budget.
- **Observability and Incident Response**: **Project-Level Notifications** enforce **observability policy**. They ensure all production environment workspaces are automatically connected to unified alert channels, reducing MTTR (Mean Time to Resolve) extension caused by monitoring gaps. This aligns with SRE principles of "automate everything" and "plan for failure."
- **Security and Compliance**: **Dynamic Credential Testing** and **Project-Level State Sharing** jointly strengthen the **Principle of Least Privilege**. They implement fine-grained access control based on identity (OIDC) and project boundaries from both deployment and testing phases, reducing secret leakage risk and simplifying compliance audits. Registry tagging helps manage supply chain security, ensuring the use of approved artifact versions.
- **Operational Efficiency and Anti-Pattern Avoidance**: These features essentially reduce **Toil**. Project-level automated inheritance (notifications, state sharing) avoids the heavy work of manually managing hundreds or thousands of workspace configurations, and is a necessary evolution for scaled operations. **Common Anti-Patterns**: Continuing to use "multi-organization" models to simulate project isolation, or using static keys in testing, both bring unnecessary management complexity and security risks, and should be avoided.
- **Best Practices**:
    1.  **Organize Resources by Project**: Group workspaces divided by business unit, environment, or application into the same project to uniformly apply governance policies (state sharing, notifications).
    2.  **Standardize Notification Routing**: Configure different notification endpoints for different projects (e.g., `prod`, `staging`, `dev`) to ensure accurate event routing.
    3.  **Testing as Code**: Write integration tests for modules and ensure test workspaces are configured with dynamic credentials, making it part of the CI/CD pipeline.
    4.  **Version Tagging**: Maintain clear environment tags (`prod`, `non-prod`) for all official modules and critical third-party modules, and establish a version promotion process.
