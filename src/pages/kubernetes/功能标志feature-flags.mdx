## 概述

功能标志（Feature Flags）是一种在不修改应用代码或部署分支的情况下，动态启用或禁用特定功能或代码路径的技术。在 SRE 实践中，功能标志是实现**渐进式交付**和**受控实验**的关键工具。它允许团队在保持核心系统稳定性的前提下，对新功能、性能优化或行为变更进行小范围测试、灰度发布或 A/B 测试，从而有效管理变更风险，并收集真实生产环境的反馈。Prometheus 从 v2.25.0 开始引入该机制，用于管理其“禁用功能”列表，体现了在可靠性和创新之间取得平衡的 SRE 原则。

## 核心概念

在 Prometheus 的上下文中，功能标志通过以下方式实现：

1.  **禁用功能列表 (Disabled Features)**：Prometheus 维护一个功能列表，默认处于禁用状态。这些功能通常被认为是**实验性**的。
2.  **`--enable-feature` 启动参数**：用户需要在启动 Prometheus 时显式传递此参数，后跟功能名称，以启用特定的实验性功能。例如：`--enable-feature=exemplar-storage`。
3.  **实验性特征**：所有通过此机制启用的功能，都附带以下声明和注意事项：
    *   **API 可能变更**：如果该功能涉及 Web API 或代码接口，其规格在未来版本中可能会发生变化。
    *   **行为可能变更**：功能的运行逻辑和效果可能与当前版本不同。
    *   **可能破坏既有假设**：例如，`@` 修饰符和负偏移（negative offset）功能打破了“查询不会在评估时间点之前查找样本”的原有假设。
    *   **稳定性不保证**：虽然会尽力维护其稳定性，但实验性功能本身可能存在不稳定因素。

这种机制的核心思想是：在功能达到足够的成熟度和广泛使用之前，将其与默认的稳定发行版隔离。

## 实践

对于 Prometheus 用户或管理员，使用功能标志的实践如下：

1.  **关注版本更新**：在每个 Prometheus 新版本发布时，查阅官方文档中更新的“Disabled Features”列表，了解新增的实验性功能。
2.  **审慎评估与测试**：在开发或测试环境中，有选择地启用感兴趣的实验性功能，评估其对现有监控数据、告警规则和仪表板的影响。
3.  **显式启用**：若决定在某个环境使用，需在 Prometheus 服务的启动命令（如 systemd unit 文件或容器启动参数）中添加 `--enable-feature=<feature_name>` 参数。
4.  **预期管理**：充分认识到所启用功能的实验性质，准备好应对 API 或行为的潜在变化，并避免对这些功能的行为做出永久性的、关键的假设。
5.  **反馈与移除**：参与社区反馈，帮助评估功能是否值得成为默认特性。对于不再需要或证明存在问题的实验功能，可随时通过移除启动参数来禁用它。

## SRE 要点

### 与可靠性、可观测性、事件响应的关联
*   **支持可靠性目标（SLO）**：功能标志是管理变更风险的重要手段，有助于避免因仓促上线新功能而引发的、影响 SLI 的可用性或性能事件。通过小范围实验，可以在不违背 SLO 的前提下验证功能价值。
*   **增强可观测性**：可以利用功能标志对新的监控指标或追踪功能进行 A/B 测试，对比其效果和开销，从而更科学地决定是否全局启用。
*   **辅助事件响应**：在复杂故障中，如果怀疑与某个新启用的实验性功能有关，可以快速通过重启服务（移除 `--enable-feature` 参数）来禁用它，作为缓解措施之一。

### 最佳实践与常见反模式
*   **最佳实践**：
    *   **文档化**：将启用的功能标志及其预期效果记录在运维手册或配置管理库中。
    *   **监控实验影响**：启用新功能后，密切监控相关系统的性能指标和错误日志，设立专门的告警。
    *   **生命周期管理**：定期审查已启用的实验功能，决定将其升级为默认功能、继续实验或彻底移除。
    *   **渐进推广**：遵循从小规模（如 canary 实例）到生产环境的渐进式启用路径。
*   **常见反模式**：
    *   **在生产环境盲目启用**：未经测试就在关键生产实例上启用实验功能。
    *   **假设永久可用**：基于实验功能的 API 或行为构建关键的自动化流程，而忽略了其未来变更的可能性。
    *   **“开启后忘记”**：启用功能后缺乏后续的跟踪和评估，导致技术债务累积。

### 相关指标（SLI/SLO/SLA）
功能标志本身不是 SLI，但它是管理影响 SLI/SLO 的变更的重要流程工具。其使用效果可以通过以下方面间接评估：
*   **变更失败率**：对比使用与不使用功能标志的变更，其导致的故障或回滚次数。
*   **平均恢复时间 (MTTR)**：通过快速禁用问题功能来缩短故障恢复时间。
*   **功能发布周期**：衡量团队利用功能标志安全地加速发布新功能的频率。
