## 概述

在 Grafana 监控可视化平台中，Dashboard 变量（Variables）是实现数据筛选和交互的核心功能。本文档基于一个已知的软件缺陷报告，分析了在启用实验性特性（Feature Toggle）`dashboardGrouping` 后，新引入的 Tab/Row 级别变量在 Dashboard 通过匿名访问方式共享时无法正常显示的问题。此问题影响了共享监控面板时的用户体验和数据筛选能力，对于需要向更广泛、未认证受众提供定制化监控视图的 SRE 实践具有重要意义。

## 核心概念

要理解此问题，需先明确以下核心概念：

- **Tab/Row 级别变量**: Grafana 于 2026 年 4 月推出的一项新功能。它允许 Dashboard 的创建者在 Tab 或 Row（可折叠区域）层级定义变量，使得变量的作用域和影响范围被限定在特定的界面区域内，而非传统的全局作用域。此功能旨在减少变量管理的复杂性。
- **匿名访问 (Anonymous Access)**: Grafana 提供的一种访问模式，允许未进行身份认证的用户通过特定链接查看公开的 Dashboard。这对于共享监控状态给外部团队或公众非常有用。
- **Feature Toggles（功能开关）**: Grafana 用于管理和逐步推出实验性或尚未完全稳定功能的一种机制。本次提到的 `dashboardGrouping` 开关即用于启用 Tab/Row 级别变量等功能。

## 实践

### 问题现象与复现

根据问题报告，该缺陷的复现步骤如下：
1.  使用具有编辑权限的账号登录 Grafana。
2.  在一个 Dashboard 中，启用 `dashboardGrouping` 功能开关。
3.  在 Tab 或 Row 层级创建新的变量。
4.  将该 Dashboard 的访问权限设置为允许匿名访问。
5.  以匿名用户身份访问该 Dashboard。
6.  **结果**：全局变量正常显示，但步骤 3 中创建的 Tab/Row 级别变量在匿名用户的界面上完全缺失，无法进行筛选操作。

### 根本原因分析

这是一个软件缺陷（Bug）。匿名访问会话与已认证的会话在加载 Dashboard 配置和变量数据时存在差异。在加载 Tab/Row 级别变量的过程中，代码可能依赖了当前用户的上下文信息或权限，导致匿名用户无法获取到这些变量的定义，从而在前端界面中不予渲染。该问题已通过 [GitHub Issue #123495](https://github.com/grafana/grafana/issues/123495) 进行跟踪。

### 规避方案与注意事项

在官方修复发布前，可采取以下规避措施：
1.  **避免在关键共享 Dashboard 中使用**: 对于需要向匿名用户展示的 Dashboard，暂时不要在其 Tab 或 Row 上使用新的变量功能。
2.  **改用全局变量**: 将相关变量定义在 Dashboard 的全局作用域，这是传统且稳定的方式，在匿名访问下能正常工作。
3.  **监控官方更新**: 密切关注 Grafana 官方发布的补丁版本（如 13.0.x 的后续版本），以获取正式修复。
4.  **测试环境验证**: 在计划使用此新功能前，务必在测试环境中模拟匿名访问进行完整验证。

## SRE 要点

### 与可靠性、可观测性的关联

此问题直接关系到 Grafana Dashboard 作为可观测性平台关键交互界面的**可靠性**。一个功能在部分用户（匿名用户）场景下失效，违反了功能的一致性原则，可能导致信息展示不全或错误，从而影响问题排查和决策的效率。SRE 需要将第三方组件的此类已知缺陷纳入风险考量，尤其在构建面向广泛受众的监控门户时。

### 最佳实践与常见反模式

- **最佳实践**:
    - **特性启用策略**: 对通过 Feature Toggle 启用的新特性，应在非关键、内部测试环境中充分评估其兼容性（尤其是与所有访问模式的兼容性），再逐步推广到生产环境。
    - **共享 Dashboard 管理**: 建立明确的共享 Dashboard 管理清单，对其使用的变量类型和访问模式进行标注和定期审查。
    - **故障预案**: 当依赖共享 Dashboard 时，应有备份方案（如提供另一个使用稳定变量的 Dashboard 链接），以防已知缺陷影响用户体验。

- **常见反模式**:
    - **盲目启用实验性特性**: 在面向生产或外部用户的 Dashboard 上直接启用未经过充分验证的实验性特性。
    - **忽视访问模式测试**: 只测试主要角色（如 SRE、开发人员）的访问路径，忽略匿名或特定角色用户的测试。

### 相关指标（SLI/SLO/SLA）

虽然此问题本身不直接产生技术 SLI，但它影响着监控系统本身的可用性和功能完备性。可以从以下角度制定相关指标：
- **功能可用率**: 对于关键共享 Dashboard，其核心筛选变量在不同访问角色下的可用率（例如，匿名用户下所有必要变量可加载）。
- **用户反馈**: 来自匿名用户关于 Dashboard 功能不全的投诉或反馈数量。
- **修复时效**: 从确认缺陷影响范围到部署修复版本的平均时间（MTTR）。

建议在定义监控平台自身的 SLO 时，考虑“共享 Dashboard 的核心功能（包括匿名访问场景）可用性”作为一项指标。
