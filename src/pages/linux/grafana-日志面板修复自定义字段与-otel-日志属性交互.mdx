# Grafana 日志面板修复：自定义字段与 OTel 日志属性交互

## 概述

在 SRE 的日常运维和故障排查中，日志分析是至关重要的环节。Grafana 作为一款强大的可视化和分析平台，其日志面板（Logs Panel）被广泛用于集中查看和过滤应用与基础设施的日志。OpenTelemetry (OTel) 作为一种云原生可观测性标准，其日志属性（Attributes）为日志条目提供了丰富的、结构化的元数据。

本次修复针对的是 Grafana 13.0.2 版本中的一个关键 Bug：当用户在日志面板中自定义了显示的字段（Custom Displayed Fields）时，若同时启用了 OpenTelemetry 日志属性功能，面板未能正确处理两者的交互，导致自定义字段的配置失效。这个 Bug 会直接影响 SRE 团队快速定位问题的能力，因为他们无法按照预设的、最相关的信息格式来查看日志。

## 核心概念

- **OpenTelemetry (OTel) 日志属性**：这是 OTel 日志数据模型中的一个核心部分。除了标准的日志消息（`Body`）外，OTel 日志可以携带一个键值对集合（`Attributes`），用于记录如 `http.method`、`db.system`、`trace.id` 等业务或技术上下文信息。在 Grafana 中启用此功能，意味着面板可以识别并展示这些结构化字段。
- **自定义显示字段**：这是 Grafana 日志面板提供的一个高级配置项。用户可以通过它来指定在日志流中具体显示哪些字段，以及它们的排列顺序。这允许用户过滤掉无关信息，聚焦于对当前排查任务最关键的字段，极大提升信息获取效率。

## 实践

此修复包含在 Grafana v13.0.2 的一个回溯提交（Backport）中，主要解决了一个前端交互逻辑的缺陷。

### 验证步骤
SRE 工程师在升级到包含此修复的版本后，可以通过以下步骤验证问题已解决：

1.  **配置自定义显示字段**：在 Grafana 的日志面板中，通过配置界面设置你希望显示的特定字段（例如，只显示 `level`, `message`, `timestamp`）。
2.  **切换 OTel 属性支持**：在面板设置中，开启或关闭“OpenTelemetry 日志属性”选项。
3.  **观察行为**：
    - 无论 OTel 属性选项是开启还是关闭状态，步骤 1 中设置的自定义字段列表都应该被严格遵守。
    - 面板中日志条目的显示应完全匹配你的自定义配置，不会因 OTel 属性开关的变化而出现字段丢失、显示多余字段或排列顺序错乱的情况。

### 架构与影响
该修复属于 Grafana 日志面板前端组件（UI）的范畴。它确保了用户配置的“显示字段”这一优先级更高的指令，在任何后端数据处理逻辑（如 OTel 属性解析）之前被正确应用和渲染。这是一个关于功能优先级和用户意图覆盖的逻辑修正。

## SRE 要点

- **与可观测性的关联**：此修复直接增强了 Grafana 日志分析的可用性和灵活性。SRE 团队可以更自信地利用自定义字段来标准化团队内的日志查看视图，同时又能无障碍地使用新兴的 OTel 标准来获取更丰富的上下文，两者不再冲突。
- **最佳实践**：
    1.  **升级与测试**：对于依赖 Grafana 日志面板进行关键监控的团队，建议在测试环境验证此修复，并在生产环境进行升级。
    2.  **文档化视图配置**：SRE 可以创建并共享针对不同故障场景（如网络问题、数据库延迟）的面板自定义字段配置模板，提升响应速度。
    3.  **结合 OTel**：积极拥抱 OTel 日志属性，它们为故障定位提供了结构化的“线索”，与自定义显示字段结合使用，可以实现既全面又聚焦的日志分析。
- **常见反模式**：忽略此类前端交互 Bug，可能导致团队成员花费大量时间调试为何精心设计的日志视图“不生效”，从而误判是数据源问题或查询语句问题，陷入排查误区。
- **相关指标 (SLI/SLO)**：此修复不直接影响基础设施的 SLI/SLO，但极大地提升了 **故障诊断效率** 和 **监控系统的可用性**。一个工作正常的日志面板是保障 MTTR（平均恢复时间）这一关键运维指标的重要工具。
