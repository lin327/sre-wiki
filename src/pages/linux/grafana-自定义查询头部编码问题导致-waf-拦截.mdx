## 概述

在构建可观测性平台时，Grafana 作为前端展示与查询入口，其与后端数据源（如 Prometheus, PostgreSQL）的交互至关重要。一个常见的架构是在 Grafana 前部署 Web 应用防火墙（WAF）以增强安全性。当 Grafana 的自定义查询头部包含非 ASCII 字符（如德语字符 `öÖäÄüÜß`）且未进行正确编码时，会直接违反许多 WAF 的安全规则和 HTTP 协议规范（RFC 9110），导致合法的数据查询请求被错误拦截，严重影响系统可观测性与运维效率。此问题揭示了在分布式系统中，看似微小的编码细节可能对端到端可靠性产生重大影响。

## 核心概念

- **自定义查询头部**：Grafana 允许用户为数据源查询附加自定义的 HTTP 头部，例如 `x-dashboard-title` 和 `x-panel-title`，用于传递上下文信息（如仪表盘或面板的标题），便于后端进行日志记录或审计。
- **非 ASCII 字符与 URL 编码**：HTTP 头部标准（RFC 9110）要求其值必须由可见的 ASCII 字符组成。非 ASCII 字符（如 UTF-8 编码的字符）必须经过 **URL 编码（Percent-encoding）** 转换，例如 `ö` 编码为 `%C3%B6`，以确保在不同系统间传输时不会被误解或过滤。
- **WAF 规则**：Web 应用防火墙通常配置了严格的规则集来防御攻击，其中一条常见规则是 **拒绝任何包含高位 ASCII 值（&gt;127）的 HTTP 头部**，因为恶意载荷（如 SQL 注入、命令注入）常利用非 ASCII 字符进行混淆。未编码的非 ASCII 标题会直接触发此类规则。

## 实践

当遇到 Grafana 查询因 WAF 拦截而失败时，可遵循以下步骤进行诊断与解决：

### 1. 确认问题
- **检查浏览器开发者工具**：在 Grafana 页面执行查询时，打开浏览器的开发者工具（F12），在“网络”选项卡中找到失败的请求。检查请求头中的 `x-dashboard-title` 和 `x-panel-title`，观察其值是否包含原始的非 ASCII 字符（如 `ö`）而非编码后的形式。
- **检查 WAF 日志**：查看 WAF（如 ModSecurity、云厂商 WAF）的日志，确认拦截原因是否为“违规 HTTP 头部值”或“非 ASCII 字符”。
- **版本回溯**：该问题在 Grafana 11.2.0 中不存在，但在更高版本（如报告的 12.2.1）中出现，表明可能是版本升级引入的回归问题。

### 2. 临时解决方案
在等待官方修复期间，可采取以下措施恢复服务：
- **修改仪表盘和面板标题**：将所有包含非 ASCII 字符的仪表盘和面板标题改为纯 ASCII 字符（例如，将“`Überwachung`”改为“`Ueberwachung`”）。这是最直接的方法，但会影响可读性。
- **调整 WAF 规则（谨慎操作）**：在 WAF 侧为来自 Grafana 服务器的、包含特定头部（`x-dashboard-title`, `x-panel-title`）的流量设置例外规则，**仅**允许这些特定头部包含非 ASCII 字符。**此操作需仔细评估安全风险**，并确保仅针对受信任来源（如 Grafana 服务器 IP）。

### 3. 永久解决方案
- **升级 Grafana**：密切关注 Grafana 官方发布，该问题（GitHub Issue #114102）的修复（通常是在代码中对这些头部值进行 `encodeURIComponent()` 编码）可能会包含在未来的版本更新中。升级到修复版本是根本解决方案。
- **贡献修复**：如果使用开源版本，可参考 Issue 中的讨论，自行应用修复补丁并重新构建 Grafana。

## SRE 要点

- **可靠性关联**：此问题直接损害了系统的**可观测性管道**的可靠性。当查询被 WAF 拦截时，SRE 失去对关键系统指标和日志的访问，无法进行有效的监控、告警和故障排查，这违反了**可靠性工程**的核心目标。
- **事件响应**：在事件发生时，快速识别此问题为“**可观测性基础设施自身故障**”至关重要。需要同时启动两条线：一是应用上述临时解决方案恢复数据流，二是向 Grafana 社区或供应商报告问题并追踪修复。
- **最佳实践与反模式**：
    - **最佳实践**：在系统间（尤其是跨越边界如 Web、API）传递包含用户生成内容或本地化文本的数据时，应始终进行 **URL 编码或 Base64 编码**。应在开发和测试环境就加入对 WAF 的兼容性测试。
    - **常见反模式**：在 HTTP 头部等受严格协议约束的位置直接使用“原始”字符串；将 WAF 规则配置得过于宽泛而没有为内部可信服务留出必要例外，或反之，为了快速修复而过度放宽安全规则。
- **相关指标（SLI/SLO/SLA）**：
    - **SLI（服务级别指标）**：可以监控“Grafana 数据源查询成功率（按请求分类）”，特别是区分因 `4xx`（如被 WAF 拦截）导致的失败。
    - **SLO（服务级别目标）**：为“可观测性数据查询可用性”设定目标，例如 99.9% 的查询请求成功返回数据。此 WAF 问题会直接影响该 SLO。
    - 在服务**SLA（服务级别协议）** 中，应明确将因安全策略（如 WAF）导致的外部依赖故障列为需共同诊断和解决的事项。
