# 解决 Grafana

## 概述

当 Grafana 后端数据库（默认使用 SQLite）在高并发场景下遇到写入冲突时，系统可能会抛出 “database is locked” 错误。该错误会导致 Grafana 部分功能暂时不可用，例如用户会话管理失败，从而影响用户体验和系统可靠性。在 SRE 实践中，识别并解决此类数据库层面的问题对于维护 Grafana 仪表板的稳定性和可观测性平台的健康至关重要。

## 核心概念

### SQLite 锁机制
Grafana 默认使用一个轻量级的嵌入式数据库 SQLite 来存储仪表板、用户和组织配置等元数据。SQLite 是一个基于文件的数据库，它通过文件锁来控制并发访问。当有多个进程或线程同时尝试写入数据库时，SQLite 会锁定整个数据库文件。如果锁定时间过长或并发请求过多，后续的写入操作将因无法获得锁而返回 “database is locked” 错误。

### WAL 模式
SQLite 有两种主要的日志模式：默认的回滚日志和 Write-Ahead Logging (WAL)。WAL 模式允许读写操作更并发地执行，通常能显著减少 “database is locked” 错误的出现。然而，即使在 WAL 模式下，高并发写入仍可能导致锁定。

## 实践

### 诊断步骤
1.  **确认错误来源**：检查 Grafana 日志，确认错误消息是否为 `"database is locked"`。错误消息 `logger=context error="database is locked"` 是一个典型的例子。
2.  **评估负载**：检查发生错误时 Grafana 的并发用户数、API 请求频率以及仪表板自动刷新的频率，确认是否存在写入密集型操作。
3.  **检查数据库文件**：定位 Grafana 的 SQLite 数据库文件（默认路径如 `/var/lib/grafana/grafana.db`），检查其大小和权限。过大的文件或不当的权限可能加剧问题。

### 解决方案
针对此问题，可采取以下一个或多个措施：

**1. 优化 SQLite 配置**
在 Grafana 配置文件 (`grafana.ini` 或环境变量) 中启用 WAL 模式：
```ini
[database]
type = sqlite3
# 启用 WAL 模式以提升并发性能
wal = true
```
此配置允许读写操作更并发地进行，是缓解该问题的首选方案。

**2. 优化 Grafana 使用**
- **减少自动刷新频率**：对于展示大量数据的仪表板，适当降低页面的自动刷新间隔。
- **审查插件和 API 使用**：检查是否有插件或外部脚本在频繁地通过 API 更新仪表板或数据源配置。

**3. 架构层面考虑**
- **评估数据库适用性**：对于大规模部署或高可用场景，SQLite 可能不是最佳选择。应考虑将 Grafana 后端数据库迁移到更健壮的数据库系统，如 **PostgreSQL** 或 **MySQL**。这需要在 Grafana 配置中明确指定数据库类型。
- **配置外部数据库**：如果已迁移到外部数据库，则需确保该数据库本身配置得当且性能良好。例如，对于 PostgreSQL，需要调整 `max_connections` 和锁相关参数。

**4. 监控与告警**
为预防此问题导致服务中断，应建立对 Grafana 后端健康状况的监控。可以监控 Grafana 日志中的错误频率，或在 Grafana 中建立关于自身性能指标的看板（如果可用）。

## SRE 要点

### 与可靠性、可观测性的关联
- **服务可用性**：“database is locked” 错误会直接导致 Grafana API 请求失败，影响用户登录、仪表板保存等核心功能，从而降低整个可观测性平台的可用性（**SLO** 影响）。
- **可观测性**：该错误本身是 Grafana 服务可靠性的一个关键信号。应将其纳入 Grafana 自身的健康监控指标中。

### 最佳实践与常见反模式
- **最佳实践**：
    - **预防优于修复**：在初始部署或规划阶段，就根据预期负载选择合适的数据库后端（SQLite 适用于小规模，PostgreSQL/MySQL 适用于生产环境）。
    - **配置监控**：对 Grafana 日志进行解析告警，监控 “database is locked” 错误率。
    - **定期维护**：对于坚持使用 SQLite 的部署，定期执行数据库备份和完整性检查。
- **常见反模式**：
    - **忽视警告**：忽略日志中的早期锁定警告，直至完全不可用。
    - **过度依赖默认配置**：在生产环境中使用未经调优的默认 SQLite 配置，未启用 WAL。
    - **单点故障**：在高可用架构中，多个 Grafana 实例共享同一个 SQLite 文件（这是不支持的），必须使用外部共享数据库。

### 相关指标（SLI/SLO/SLA）
- **SLI（服务级别指标）**：Grafana API 请求的成功率（特别是 `/api/` 端点），错误日志中 “database is locked” 出现的频率。
- **SLO（服务级别目标）**：例如，确保 Grafana 核心 API（如仪表板查询）的可用性达到 99.9%，因数据库锁定导致的错误率应低于 SLO 容忍的 Error Budget。
- **SLA（服务级别协议）**：对内部用户的承诺中，应包含基于上述 SLO 的条款。
