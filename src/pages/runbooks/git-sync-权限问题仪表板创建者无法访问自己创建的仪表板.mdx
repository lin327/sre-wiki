# Git-sync 权限问题：仪表板创建者无法访问自己创建的仪表板

## 概述

在 Grafana 中启用基于 Git 的配置管理（Git-sync）是实践配置即代码（Configuration as Code）的重要方式，它能确保仪表板和文件夹配置的版本化与可审计性。然而，在特定的 Git-sync 场景下，存在一个严重的权限分配缺陷。本页面详细记录了该问题的发现、根本原因、临时规避方案及其对站点可靠性工程（SRE）实践的启示。该问题破坏了 Grafana 权限模型的预期行为，直接影响了用户的工作流程和对系统的信任，是 SRE 团队在实施 Git-sync 时必须关注和处理的可靠性风险。

## 核心概念

- **Git-sync**: Grafana 的一项功能，允许将实例中的仪表板、文件夹等配置与 Git 仓库进行同步。当开启后，通过 Grafana UI 或 API 进行的更改可以自动推送到指定的 Git 仓库。这为配置提供了版本历史、代码审查和灾难恢复能力。
- **预期权限模型**: 根据 Grafana 官方文档，当用户创建仪表板或文件夹时，他们应自动被授予该资源的 **Admin 权限**。这意味着创建者完全控制其创建的资源，无需额外的权限分配步骤。
- **问题行为**: 在启用了**全局 Git-sync** 的实例中，上述权限授予机制失效。通过 UI 创建仪表板的用户（例如具有 Editor 角色的用户）在创建后立即无法访问该仪表板，API 返回 **403 Forbidden** 错误。这表明权限系统与 Git-sync 流程之间存在集成缺陷。

## 实践

### 问题诊断

1.  **重现路径**:
    *   在 Grafana 实例（测试环境为 12.4.0 版本）中，为整个实例配置 Git-sync。
    *   以拥有 “Editor” 角色（非组织管理员）的用户身份登录。
    *   在 Git-sync 管理的文件夹内创建一个新的仪表板。
    *   创建操作完成后，尝试导航到新创建的仪表板 URL。
2.  **关键错误信息**: 浏览器控制台或网络面板将显示对 `apis/dashboard.grafana.app/v1beta/namespaces/default/dashboards/<dashboard-id>/dto` 的 GET 请求返回 **403** 状态码。这确认了权限检查失败，而非仪表板不存在（404）。

### 临时规避方案

在官方修复发布前，管理员或具有组织管理员权限的用户可以采用以下方法作为临时解决方案：

1.  **手动权限授予**: 在仪表板创建后，立即由管理员（或文件夹的 Admin）进入该仪表板的 **权限（Permissions）** 设置页面。
2.  **添加创建者用户**: 将创建该仪表板的用户添加到权限列表中，并为其分配 **“Admin”** 角色（或至少 **“Can Edit”** 角色，如果需要编辑权限）。
3.  **自动化规避（可选）**: 对于频繁创建仪表板的场景，可以考虑编写一个简单的自动化脚本（如使用 Grafana API），在检测到新仪表板通过 Git-sync 创建时，自动查询其创建者并授予相应的权限。这增加了运维复杂度，仅作为临时措施。

### 官方状态与追踪

此问题已在 Grafana 官方仓库中以 Issue [#113829](https://github.com/grafana/grafana/issues/113829) 形式提交。问题状态显示已被确认（由官方成员回复“复现确认”），属于 Bug。解决方案预计将在 Grafana 的后续版本中修复。SRE 团队应监控该 Issue 的进展，以在官方补丁发布后及时更新实例。

## SRE 要点

- **与可靠性的关联**: 该缺陷直接破坏了 **自助服务（Self-Service）** 模型的可靠性。用户期望能够创建并立即管理自己的资源，但 Git-sync 的引入意外地阻碍了这一核心功能，导致用户工作流中断，降低了平台的可用性和用户体验。
- **可观测性与事件响应**: 此类问题的早期发现依赖于良好的 **可观测性**。用户提交的 403 错误日志是关键信号。SRE 团队应监控仪表板创建后的首次访问失败率（可视为一种自定义 SLI），并设置告警，以便在问题影响范围扩大前及时响应。
- **最佳实践与反模式**:
    *   **最佳实践**: 在升级 Grafana 或开启新特性（如全局 Git-sync）前，应在**预发布环境**中进行全面测试，特别是覆盖**权限模型**和**用户工作流**的端到端测试。
    *   **常见反模式**: 假设所有组件（Git-sync、权限系统）独立工作且集成完美无瑕。在复杂的系统中，跨模块的集成测试至关重要。
- **相关指标（SLI/SLO）**:
    *   **SLI**: `成功创建并访问仪表板的用户百分比` 或 `仪表板创建后一分钟内的 403 错误率`。
    *   **SLO**: 承诺在配置变更（如启用 Git-sync）后，用户的自助服务功能（如创建资源）保持 99.9% 的成功率，中断时间计入 Error Budget。
- **SRE 行动清单**:
    1.  **评估影响**: 检查生产环境是否已启用全局 Git-sync，并评估已受影响的仪表板和用户。
    2.  **实施规避**: 根据上述临时方案，为受影响的用户手动修复权限。
    3.  **配置管理**: 将此已知问题及规避步骤记录在运行手册（Runbook）中。
    4.  **升级监控**: 监控官方 Issue，计划在下一个维护窗口内升级 Grafana 版本以获取官方修复。
    5.  **改进流程**: 在未来的配置即代码（CaC）实践中，将“权限验证”加入部署检查清单。
